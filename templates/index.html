About JA4 Fingerprints

JA4 identifies TLS clients by their handshake characteristics — useful for application identification, anomaly detection, and threat hunting. JA4LookR resolves fingerprints against a locally cached JA4DB (refreshed hourly) with exact, near, cipher-variant, wildcard, and partial matching, and optionally pivots to VirusTotal Intelligence.

  • JA4: TLS client fingerprinting · JA4H: HTTP · JA4S: TLS server
  • Wildcards: use * for any section, e.g. t13d190900_*_97f8aa674fd9

How the risk engine works

Every parsed fingerprint is scored for the indicators threat hunters look for. Flags stack into an overall level (none → low → medium → high):

  • Legacy TLS (11/10/s3…) — pre-TLS-1.2 is rare for legitimate clients today → high.
  • Direct-to-IP / no SNI (the i char, e.g. t13i…) — browsers almost always send SNI; IP-only TLS is typical of C2 → medium.
  • No ALPN (00) — no negotiated protocol; with a browser-like handshake this hints at a minimal/custom stack → medium.
  • Combo escalation — IP-only and no-ALPN together is the classic C2 shape and escalates to high.

Worked examples: t13d1516h2_… (Chrome 137) scores none; t12d210600_… (Cobalt Strike, no ALPN) medium; t13i190800_… (Sliver, IP-only + no ALPN) and t12i190700_… (Metasploit) score high.

🔌 API Access

Programmatic access via REST API — same parity as the web form (JA4DB matches, parsed components, optional VirusTotal pivot, YARA rule):

GET /api/lookup/<fingerprint>?vt=1&enrich=1

Examples:

curl http://localhost:5000/api/lookup/t13d1516h2_8daaf6152771_b0da82dd1658
curl 'http://localhost:5000/api/lookup/t13d190900_*_97f8aa674fd9?vt=1'

Prefer the terminal? python3 ja4lookr.py --help exposes the same engine with batch CSV, JSON file output, and YARA generation.
