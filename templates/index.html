About JA4 Fingerprints

JA4 identifies TLS clients by their handshake characteristics — useful for application identification, anomaly detection, and threat hunting. JA4LookR resolves fingerprints against the local JA4DB cache (exact, near, wildcard, and partial matches) and optionally pivots to VirusTotal Intelligence with per-file network indicators.

  • JA4: TLS client fingerprinting
  • JA4H: HTTP client fingerprinting
  • JA4S: TLS server fingerprinting
  • Wildcards: use * for any section, e.g. t13d190900_*_97f8aa674fd9
Examples:
  t13d1516h2_8daaf6152771_b0da82dd1658
  t13d190900_*_97f8aa674fd9  (wildcard cipher)
  *_8daaf6152771_*  (any client sharing this cipher hash)
Disable for faster lookups when VT quota matters. Has no effect if VT is not configured.
Up to 100 fingerprints, one per line. Wildcard patterns are accepted.

🔌 API Access

Programmatic access via REST API — same parity as the web form (JA4DB matches, parsed components, optional VirusTotal pivot, YARA rule):

GET /api/lookup/<fingerprint>?vt=1&enrich=1

Examples:

curl http://localhost:5000/api/lookup/t13d1516h2_8daaf6152771_b0da82dd1658
curl 'http://localhost:5000/api/lookup/t13d190900_*_97f8aa674fd9?vt=1'

Prefer the terminal? python3 ja4lookr.py --help exposes the same engine with batch CSV, JSON file output, and YARA generation.
